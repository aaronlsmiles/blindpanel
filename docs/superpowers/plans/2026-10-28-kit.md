# blindpanel v0.1 (the kit) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-package, MIT rating kit that turns a `study.yaml` into a blinded rating page, stores opt-in submissions, and shows a rater where they land against a reference panel and against automatic metrics. A clean clone plus `npm run setup` runs it with no accounts.

**Architecture:** One TypeScript ESM package with subpath exports (`blindpanel`, `/stats`, `/ui`, `/server`) and a CLI. The browser code (ui, order, payload, stats) has **no runtime dependencies**, so `blindpanel build` produces a static site without a bundler. zod (schema) and yaml (config) are used at build time and on the server only. The server handlers are web-standard `Request → Response` functions over three stores (memory, JSONL file, Supabase via plain `fetch`).

**Tech stack:** Node ≥ 22 (target 24 LTS), TypeScript 7.0.2, Vitest 5.0.5 + jsdom, @playwright/test 1.64.1 + @axe-core/playwright, zod 4, yaml 2, PGlite (Postgres in WASM, dev only) for the SQL tests, ffmpeg (one-off, to make the synthetic clips).

## Reconciliation (sub-plan C against the master draft and the design pass)

The design pass's 8 changes are adopted. Where this phase's brief names something differently, the brief wins:

| Topic | Master draft | Design pass | Sub-plan C |
|---|---|---|---|
| Scale control | `aria-pressed` buttons | native radios in fieldsets | **radios** (keys 1–5, Enter, Shift+Enter, Space, R; switchable) |
| Mount API | `mountSession` / `mountResults` | one `mount()` | **`mountSession` + `mountResults`**, each returning `{destroy, getState, on}` |
| Setup | `npm run setup [-- --ci]` | `npm run quickstart [-- --smoke]` | **`npm run setup`**; `--ci` absorbs the smoke checks |
| CI example | `examples/synthetic` | `examples/hello` | **`examples/synthetic`** (three tiny CC0 clips) |
| SQL | `sql/schema.sql` | `supabase/migrations/0001…` | **`sql/schema.sql`** |
| Order | seeded per session | SHA-256 → xoshiro128** → Fisher–Yates | **design pass**, documented in `docs/order.md` with a Python reference and test vectors |
| Codes | seeded opaque codes | opaque media paths | **seeded codes** (`c` + 5 base32 chars from SHA-256 of seed and item id); media served under those codes |
| Caps | daily cap | daily 500 + total 20,000 | **both**, in a `settings` table, enforced by an advisory-locked trigger |
| Explorer dependency | git dependency | vendored tarball | tarball built by `release.yml` (`npm pack`); **consumption is Phase 4** |
| React wrapper | none | `blindpanel/react` | **deferred to Phase 4**, where it can be tested inside the explorer |
| Invited mode, middleware | in config | deferred to v0.2 | **v0.2** (kill rule: config v0 covers what the two examples use) |
| `db check` | none | CLI command | **Phase 4** (needs the live project) |

Blinding is honest: the page, its URLs and its requests carry no model names until the visitor finishes. The kit cannot remove C2PA credentials embedded in byte-exact clips, and a determined visitor can match clips against a public release. `docs/blinding.md` says so.

## Data shapes (the contract every task uses)

```ts
// compiled study.json: everything the page may know before the visitor finishes
interface Study {
  blindpanel: 1; id: string; instrument: string; text_sha256: string;
  seed: string;
  scales: Record<string, { min: 1; max: 5; labels: string[] }>;
  questions: { id: string; part: "baseline" | "clips"; text: string; notes: string[]; scale: string }[];
  parts: {
    baseline: { intro: string; items: { code: string; image: string }[] } | null;
    clips: { intro: string; watch_note: string; clip_seconds: number; session_size: number;
             extend: boolean; video: { loop: boolean; muted: true; autoplay: "unless_reduced_motion" };
             items: { code: string; video: string; reference: string /* baseline code */ }[] };
  };
  modes: { public: { submit: boolean; tally: boolean; min_crowd_n: number } };
  endpoints: { submit: string; tally: string; reveal: string };
}
// compiled reveal.json: fetched only after completion (the declared blinding exemption)
interface Reveal {
  items: Record<string, { label: string; meta: Record<string, string | number>; link?: string }>;
  reference: {
    raters: string[]; author_slot?: string;
    ratings: Record<string /*question*/, (number | null)[][] /* raters × clip codes in study order */>;
    baseline: (number | null)[][] /* raters × baseline codes */;
    metrics: { id: string; label: string; values: (number | null)[] /* per clip code */;
               published?: Record<string /*question*/, { rho: number; ci95: [number, number]; n: number }> }[];
    published_alpha?: Record<string, number>;
    attribution?: string;
  } | null;
}
// a submission (POST body); no timestamps, no free text
interface Submission {
  format: "blindpanel/1"; study: string; instrument: string; session: string /* uuid v4 */;
  order: { baseline: string[]; clips: string[] };
  answers: { baseline: Record<string, Record<string, number>>; clips: Record<string, Record<string, number>> };
  delivery: { autoplay: boolean; keyboard: boolean; duration_s: number; ui: string };
}
```

### Task 2: Seeded RNG and visitor order

**Files:** `src/core/rng.ts`, `src/core/order.ts`, `scripts/order_ref.py`, `tests/order.test.ts`, `tests/fixtures/order-vectors.json`, `docs/order.md`

The scheme: `digest = SHA-256(utf8("<seed>:<part>:<participant>"))`; xoshiro128** state = the first 16 bytes as four little-endian uint32 (all-zero state replaced by `[1,0,0,0]`); `below(n) = floor(next() * n / 2^32)` (multiply-shift); Fisher–Yates from the top (`for i = n-1 … 1: j = below(i+1); swap(i, j)`).

- [ ] Write `scripts/order_ref.py` (stdlib only) implementing the same scheme and printing vectors for seeds `"demo"`, `"20260813"` × parts `clips`, `baseline` × participants `"00000000-0000-4000-8000-000000000000"`, `"a"`, over `["x0".."x9"]`; commit its output as `tests/fixtures/order-vectors.json`.
- [ ] Failing tests: `shuffle` matches every vector; first ten `next()` outputs for seed `"demo:clips:a"` match the Python list; `participantOrder` is deterministic for one session and differs across sessions; baseline block 1 contains exactly the reference panels of the first `session_size` clips, in seeded baseline order; block 2 contains only panels not yet asked.
- [ ] Implement; tests pass; commit.
